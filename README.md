# X-Sense Binding

This binding integrates [X-Sense](https://www.x-sense.com) home safety devices into openHAB: smoke, carbon monoxide (CO), combined smoke/CO, heat and water leak detectors as well as door and motion sensors.
Sensors are connected through the X-Sense SBS50 Base Station, which links the battery powered sensors via a proprietary RF protocol and connects to the network via 2.4 GHz Wi-Fi.

## Scope and Cloud Usage

The X-Sense system does not provide a documented local API.
Communication is therefore performed through the X-Sense cloud services using the credentials of your X-Sense account.
The binding polls the inventory and reads the state reported by the SBS50 base station over HTTPS.

Polling reads the state at the time of each request.
An alarm that starts and clears between two polls can be missed.
Notifications generated by openHAB therefore supplement the detector's own alarm, they do not replace it.

The binding maps the X-Sense cloud data model to a four level thing hierarchy: `account` → `home` → `station` → sensor.
Multiple accounts, multiple homes per account, multiple base stations per home and multiple sensors per station are supported.

## Getting Started

1. In the X-Sense app, make sure the base station is running the latest firmware.
1. Share the home with a dedicated X-Sense account for openHAB so the binding and the mobile app can maintain separate sessions.
1. In openHAB, add an `account` bridge thing with that account's email and password.
1. Once the `account` bridge is online, your home appears in the inbox — add it.
1. Adding the `home` thing surfaces its base stations and their smoke/water sensors — add the `station` first, then the sensors.

## Binding Configuration

The binding configuration (Settings → Add-on Settings → X-Sense Binding) provides defaults for all accounts:

| Name            | Type    | Description                                                                  | Default |
|-----------------|---------|------------------------------------------------------------------------------|---------|
| refreshInterval | integer | Default interval in seconds for polling inventory and device states (min 30) | 300     |

Account things inherit this value unless they configure their own interval.

## Supported Things

| Thing Type UID | Type   | Description                                                                  |
|----------------|--------|------------------------------------------------------------------------------|
| xsense:account | Bridge | Represents your X-Sense account (cloud connection)                           |
| xsense:home    | Bridge | A home (house) registered in the account                                     |
| xsense:station | Bridge | X-Sense SBS50 Base Station                                                   |
| xsense:smoke   | Thing  | Smoke detector (XS01-M, XS0B-MR, XS0D-MR, SD11-MR, XP02S-MR)                 |
| xsense:co      | Thing  | Carbon monoxide detector (XC01-M, XC0C-MR, XC0M-MR)                          |
| xsense:combo   | Thing  | Combined smoke and CO detector (SC01-MR, SC07-MR, XP0A-MR, XP0H-MR, XP0P-MR) |
| xsense:heat    | Thing  | Heat detector (XH02-M)                                                       |
| xsense:water   | Thing  | Water leak detector (SWS51, SWS0A)                                           |
| xsense:door    | Thing  | Door and window contact sensor (SDS0A)                                       |
| xsense:motion  | Thing  | Motion sensor (SMS0A)                                                        |

Only devices connected to an SBS50 base station are supported.
Stand-alone Wi-Fi devices (e.g. XS01-WX, XC04-WX, SC07-WX) and thermo-hygrometers (STH51, STH0A, STH0B) are recognized by the cloud API but not yet exposed as things.

## Discovery

Discovery imports the account tree progressively, starting automatically as soon as the `account` bridge goes online (or manually via a scan):

1. Once the `account` bridge is online, all homes of the account appear in the inbox.
1. Once a `home` thing has been added, its base stations and their sensors appear.
   Add the base station before its sensors.

Discovered things are labeled with the names given in the X-Sense app.
Devices without a name are labeled with model and serial number, e.g. `XC01-M 0000000C`.

Each inventory poll re-publishes all levels whose home thing already exists, so after approving a home the next level appears without a manual rescan.
Unsupported device models are logged on debug level, please report them so support can be added.

## Channels

The `home`, `station` and `account` bridges have no channels.
Their state is reflected in the thing status and the thing properties (e.g. home name, model, serial number).

Sensor things have the following channels:

| Channel              | Type                 | Read/Write | Thing Type    | Description                                                                       |
|----------------------|----------------------|------------|---------------|-----------------------------------------------------------------------------------|
| `alarm#smoke`        | Switch               | R          | `smoke`       | `ON` while the detector reports a smoke alarm                                     |
| `alarm#co`           | Switch               | R          | `co`          | `ON` while the detector reports a carbon monoxide alarm                           |
| `alarm#alarm`        | Switch               | R          | `combo`       | `ON` while the detector reports a smoke or carbon monoxide alarm                  |
| `alarm#heat`         | Switch               | R          | `heat`        | `ON` while the detector reports a heat alarm                                      |
| `alarm#water`        | Switch               | R          | `water`       | `ON` while the detector reports a water leak                                      |
| `measurement#co`     | Number:Dimensionless | R          | `co`, `combo` | Current carbon monoxide concentration in ppm                                      |
| `measurement#coPeak` | Number:Dimensionless | R          | `co`, `combo` | Highest carbon monoxide concentration recorded by the detector, in ppm (advanced). Only present when the detector reports a peak value, see below |
| `state#contact`      | Contact              | R          | `door`        | `OPEN` or `CLOSED`                                                                |
| `state#motion`       | Switch               | R          | `motion`      | `ON` while the sensor detects motion                                              |
| `device#battery`     | Number               | R          | all           | Battery level in percent, reported in four steps (0, 33, 67, 100)                 |
| `device#lowBattery`  | Switch               | R          | all           | `ON` when the battery level is at one of the two lowest steps                     |
| `device#signal`      | Number               | R          | all           | Radio signal strength between sensor and base station (0 = none, 3 = best)        |

The base station does not report a CO peak value for every detector (e.g. not for the XC01-M).
The `measurement#coPeak` channel is therefore added when a detector reports a peak value for the first time.
A `measurement#coPeak` channel created by an earlier version is removed when the detector reports no peak value, unless an item is linked to it.

Missing or invalid values are set to `UNDEF`.
When the sensor reports that it is not connected to the base station, the thing goes offline and all channels become `UNDEF`.

Combined smoke/CO detectors report a single alarm status, so `alarm#alarm` does not distinguish between smoke and carbon monoxide.

Support for CO, combined, heat, water leak, door and motion devices is based on the station data documented by the [Python X-Sense client](https://github.com/theosnel/python-xsense) and the [Home Assistant integration](https://github.com/Jarnsen/ha-xsense-component_test) and has not yet been verified with all models.
Please report models that do not work as expected, together with a debug log (see below).

## Troubleshooting

### Offline States

A sensor is `OFFLINE` when the base station explicitly reports it as disconnected (`online`/`onLine` set to `0` or `false`).
Values the station still delivers for such a sensor are outdated: its channels are set to `UNDEF` until the station reports the sensor online again.
When the base station itself is offline, all its sensors are `OFFLINE` (bridge offline) with `UNDEF` channels.

### Several Reports for One Device

A base station may report a device more than once, e.g. in its device list and in a separate record keyed by the device id.
The binding combines these records:

- Records are assigned to a device only when their identifiers name exactly one device of the station; other records are ignored.
- Values reported by only one record, or identically by several, are taken over.
- Contradicting values: an offline report wins over an online report, and an alarm wins over "no alarm".
  All other contradicting values become `UNDEF`.

If several devices of a base station report the same serial number, the binding cannot tell their states apart.
The thing configured with that serial number goes `OFFLINE` (configuration error) with `UNDEF` channels, and these devices are not offered in the inbox.

### Debug Log

To analyze how the base station reports its devices, enable debug logging in the openHAB console:

```shell
log:set DEBUG org.openhab.binding.xsense
```

For each poll the log contains one line per device with its model, the result and the names of expected fields that were not reported or contradicted each other, e.g. `station <serial>, model XS01-M: missing rfLevel`.
The reported device data itself is not logged.
Restore the default level with `log:set INFO org.openhab.binding.xsense`.

## Full Example

### Thing Configuration (`.things` file)

Things can be created through auto-discovery or manually via a `.things` file.
The `deviceSn`/`stationSn`/`houseId` values are taken from the X-Sense app or from a discovered thing's properties.

```java
Bridge xsense:account:myaccount "My X-Sense Account" [ email="user@example.com", password="secret" ] {
    Bridge home h1a2b3 "My Home" [ houseId="h1a2b3" ] {
        Bridge station sbs50 "Hallway Base Station" [ stationSn="SBS50-1234" ] {
            Thing smoke kitchen "Kitchen Smoke Detector" [ deviceSn="DEV567" ]
            Thing water basement "Basement Water Sensor" [ deviceSn="DEV890" ]
            Thing co garage "Garage CO Detector" [ deviceSn="DEV345" ]
        }
    }
}
```

### Item Configuration (`.items` file)

```java
Switch KitchenSmokeAlarm   "Kitchen Smoke Alarm"   <fire>    { channel="xsense:smoke:myaccount:h1a2b3:sbs50:kitchen:alarm#smoke" }
Number KitchenSmokeBattery "Kitchen Battery [%d %%]" <battery> { channel="xsense:smoke:myaccount:h1a2b3:sbs50:kitchen:device#battery" }
Switch KitchenSmokeLowBat  "Kitchen Low Battery"   <lowbattery> { channel="xsense:smoke:myaccount:h1a2b3:sbs50:kitchen:device#lowBattery" }
Switch BasementWaterLeak   "Basement Water Leak"   <water>   { channel="xsense:water:myaccount:h1a2b3:sbs50:basement:alarm#water" }
Switch GarageCoAlarm       "Garage CO Alarm"       <alarm>   { channel="xsense:co:myaccount:h1a2b3:sbs50:garage:alarm#co" }
Number:Dimensionless GarageCo "Garage CO [%d ppm]" { channel="xsense:co:myaccount:h1a2b3:sbs50:garage:measurement#co", unit="ppm" }
```

### Rule Example

```java
rule "Smoke alarm notification"
when
    Item KitchenSmokeAlarm changed to ON
then
    sendBroadcastNotification("Smoke alarm in the kitchen!")
end
```

## Building

This repository contains the binding module.
It uses the Maven parent and build conventions of openHAB Add-ons.
The tested openHAB Add-ons revision is `ef448827d9fff145b86d0662703871129cd4dfc8`.
With Java 21 and Maven installed, run these commands from this repository:

```sh
git clone https://github.com/openhab/openhab-addons.git ../xsense-build
git -C ../xsense-build checkout ef448827d9fff145b86d0662703871129cd4dfc8
module=../xsense-build/bundles/org.openhab.binding.xsense
mkdir -p "$module"
cp -R src pom.xml README.md NOTICE "$module/"
mvn -f "$module/pom.xml" package
```

The package build runs the unit tests and writes the binding JAR to the module's `target/` directory.
The binding uses the HTTP client of the Java 21 runtime and imports no Jetty packages, so the same JAR runs on openHAB 5.3.0.M5 (Jetty 9.4) and on later 5.3.0 snapshots (Jetty 12.1).
